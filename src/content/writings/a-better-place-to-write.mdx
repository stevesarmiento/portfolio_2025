## The page should get out of the way

Most writing tools begin with a generous promise: put the cursor down and start.
Then the interface arrives. There are settings to configure, blocks to arrange,
and publishing rituals to remember. The machinery becomes louder than the
thought.

This little corner of the site works from a simpler rule: an article is a
`.mdx` file, and the file is already the source of truth. Markdown handles the
common shapes. React is there when an idea needs to become something a reader
can touch.

  A writing system should make the ordinary path boring. Headings, links,

### A small, legible contract

Every article starts with a compact metadata export. The rest is just prose:

```tsx title="a-note.mdx" {2}
export const article = {
  title: "A note worth keeping",
  publishedAt: "2026-08-29",
  draft: false,
};
```

The filename becomes the URL. Drafts stay local. Invalid metadata fails closed
instead of quietly producing a half-working page.

## Markdown, with room to move

Markdown is good at structure because it does not make the structure feel
precious. A list can stay a list:

- Capture the idea while it is still sharp.
- Give every section one clear job.
- Add an interactive example only when it explains something prose cannot.

And a small comparison can stay a table:

| Need | Default |
| --- | --- |
| Long-form prose | Markdown |
| Syntax highlighting | A fenced code block |
| Something interactive | An imported React component |

The goal is not to turn every paragraph into software. It is to leave a door
open for the moments when software is the clearest explanation.

## Details carry the reading experience

The page uses the same warm paper color, restrained dividers, and dashed rails
as the rest of the portfolio. Code lives on a translucent light surface rather
than becoming a dark rectangle in the middle of the article. Headings expose
stable links, and the table of contents appears only when the viewport has room
for it.

> The best publishing feature is the one that makes publishing feel ordinary.

Those choices are quiet, but they compound. A reader should notice the idea
before they notice the renderer.[^quiet]

[^quiet]: Quiet does not mean plain. It means every visible decision is helping
    the content rather than competing with it.

## Keep the authoring path short

To publish the next note, duplicate the template, choose a slug, fill in the
metadata, and write. There is no dashboard to maintain and no second copy of the
content to synchronize.

That is enough system for now. The rest can be earned by an article that
actually needs it.
